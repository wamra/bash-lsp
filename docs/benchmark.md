# Benchmark: the truth-file suite

Server: bash-lsp. Truth files committed in `cb8d629`; result file `bench/results/suite-bash-lsp-m4-t14.json` committed in `caa0133`.

This file is generated by `bench/report.py --m4` from the result files; do not edit it by hand.

## Limits

- The corpus (`bench/testdata/corpus2`) and every expectation were written by an agent, from the bash manual and the LSP 3.17 typings, before any server output was seen. No human has audited them.
- One machine, macOS only. Linux and Windows are pending: not measured, for bash-lsp, the competitors or the oracle.
- Competitors: only binaries already installed on this Mac were run; `shuck` and `bashd` are not installed, so they were not run. bash-language-server ran with its default settings and, for each failing case, with every setting its own config names (see the settings review).
- The run oracle (`bench/oracle_trace.py`) decides only what a run of the corpus script can show: which definition a call ran, what a variable held, whether a sourced file's function was defined at the call. It skips every script that fails its trace guard, and most cases are not of a kind a run decides.
- ShellCheck is on for bash-language-server (its default, ShellCheck 0.11.0 on PATH) and off for bash-lsp (`bench/config-shellcheck-off.toml`), so the diagnostics rows compare a server that wraps ShellCheck with native findings. shfmt is not installed, so bash-language-server's formatting returns no edits and S140 and S155 pass with 0 edits.
- "n/a" (not offered) is decided mechanically from the capabilities a server advertises in `initialize`. bash-language-server's README lists scope-based jump to declaration and find references under "To be implemented", which is where its scope failures come from. A failing case whose detail reads "unconsumed expect keys ... (runner bug)" failed because the server returned an empty or error response before the checker read the case's keys; that is the runner's text, not a harness bug.
- bash-lsp runs with shellcheck disabled (`bench/config-shellcheck-off.toml`), so its diagnostics are the native ones.
- Each case runs on a fresh server over a fresh copy of the corpus; the file is opened and the harness waits 2 s before asking. Latency-sensitive failures were re-run with 6 s in Task 12 (the failing set is the same in this run) and stayed failing.
- Case expectations were frozen before the first result; none was edited afterwards. Gating cases are the contract, design cases (soft design assumptions) are reported separately.

## Run oracle: `bash-trace` and `manual` expectations against real bash

`bench/oracle_trace.py` copies `corpus2` to a temporary directory and runs each decidable script with `env -i PATH=/usr/bin:/bin` under GNU bash, version 3.2.57(1)-release (arm64-apple-darwin25) (sandboxed: no network, no writes outside the temporary directory). A static guard refuses any script that has a command word that is not a corpus function or one of `echo printf : true false test [ local declare export unset return source . shift set read eval`, any redirection but a here-string, backticks, process substitution, `read` not fed by a here-string, a non-literal `eval` or an unresolvable `source`.
